# What 1,000 popular repositories can run on your machine

*November 2026. BeforeOpen 0.1.2 read the 1,000 most starred repositories on GitHub without running anything.*

**994 of 1,000 were scanned.** The other 6 were too large to download in ten minutes or lost the connection.

## Key findings

1. **72.6% contain something that can run code before you run the project yourself:** install scripts, git hooks, build configuration that is code, editor or agent settings.
2. **49.7% now include instructions for AI agents.** 38.2% have an `AGENTS.md`, 32.3% have skills and 22.8% a `CLAUDE.md`. Agents read those files as orders.
3. **6.3% ship hooks for AI agents**, commands that run while the agent works, and 4.6% ship MCP servers that start a program. 10 repositories approve their own MCP servers in advance, which skips the question that the agent would ask you.
4. **Only 1 of 994 uses a VS Code task that runs when the folder opens**, and it is VS Code itself. That same feature is the favourite trick of fake job interviews. In a project you were sent, it is a reason to stop.
5. **37.1% run something while dependencies are installed** and 27.4% activate git hooks for you.

None of this is malicious by itself. It shows how much code runs before anyone reads it, and that AI agents have added a new layer of it.

## The high findings were all false alarms

BeforeOpen marked 53 repositories (5.3%) as `high`. Every one was reviewed by hand, looking at the lines that triggered it rather than auditing the whole project, and **none looked malicious**:

- Security and cryptocurrency projects whose normal code looks like an attack: exploit frameworks, blockchain clients, lists of dangerous strings.
- Text that only looks like a command: install instructions printed as messages, and lists of file names that tools use to *protect* keys.
- Tools that build encoded commands on purpose, to run code in a container or on another machine.
- Scripts that install tools inside a dev container, which do not touch your machine.
- Real configuration choices worth knowing: projects that approve their MCP servers in advance.

One repository includes a 98 KB obfuscated library from another company. Its description says that it handles sign-in. No sign of harm was found, but obfuscated code cannot be checked. It is not named here.

The lesson is about base rates. In a famous repository, a `high` finding is almost always a legitimate oddity. In a project that a stranger sent you, the same finding deserves your attention. The study also shows where the noise comes from, so it can be reduced: scripts that only run inside containers, and text found far from the command that actually runs.

## Method

- **List:** the 1,000 most starred repositories according to the GitHub search API on 2026-11-25. They have between 35,000 and 566,000 stars.
- **Download:** the last commit only, without files over 8 MB. More than 30 GB in total. Nothing was checked out or run.
- **Tool:** BeforeOpen 0.1.2, with default rules. 989 scans were complete; the rest had a file too large to read.
- **Counting:** a repository counts once per row, however many files it has.
- Results per repository are not published, so that no project is singled out. The list and the tool are public, so anyone can repeat it.

How well BeforeOpen finds real attacks is measured separately in [detection.md](detection.md).
